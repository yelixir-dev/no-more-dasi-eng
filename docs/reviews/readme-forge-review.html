Verdict

전체 평가

견고한 스킬. 게이트 중심 설계가 nomoredasi와 같은 철학(검증은 코드로)이라 우리 프로젝트와 잘 맞고, 실제 README 2종 생성에 검증됐다. 아래 이슈들은 치명적이지 않으며 1개만 중간 등급.

  • 결정적 게이트(check_readme.py)가 앵커 슬러그·상대 링크·이미지 실존·EN/KO 펜스/헤딩/배지 동등성까지 실제로 검증
  • anatomy의 '사실만' 규칙(번호·버전 추측 금지)이 생성물 품질을 구조로 강제
  • README-I18N 셀렉터 관례가 다국어 README 세트를 표준화
  • FUNDING 키 화이트리스트 등 세부까지 테스트됨

Findings

버그·개선점 (심각도순)

항목유형내용심각도
필수 섹션 존재 미검증버그/설계 갭게이트는 '있는 것의 일관성'만 검사하고 Install·What it does 같은 필수 섹션의 부재는 통과시킴. anatomy는 관례일 뿐 코드 강제가 아님중간
중복 heading 슬러그 미모델링버그GitHub는 같은 제목에 -1, -2 접미사를 붙이는데 gh_slug는 중복을 모델링하지 않음 — 중복 헤딩 있는 README의 앵커가 조용히 깨질 수 있음낮음
스펙 드리프트 (v0.2.0)불일치SKILL.md는 'em dash & content' 검사를 표방하지만 check_readme.py에 해당 로직이 없음 — 문서와 게이트가 어긋남낮음
FUNDING.yml 키만 검증개선점플랫폼 키 검증은 하지만 YAML 파싱은 안 함 — 문법 오류가 통과됨 (pyyaml 있으면 safe_load 제안)낮음
링크 정규식 경계개선점rel_links/img srcs의 [^)]+ 패턴은 파일명에 괄호가 있으면 깨짐. 드물지만 수정 쉬움낮음
프리뷰 스크립트 부재개선점preview-sim.md는 GitHub 렌더 미리보기를 요구하는데 스크립트가 references만 있고 scripts/엔 없음. qlmanage 기반 헬퍼 제공 제안낮음

Suggestions

제안

  1. 게이트에 필수 섹션 존재 검사 추가 (템플릿의 anatomy를 코드로). 가장 가치 있는 갭.
  2. FUNDING.yml은 pyyaml 가용 시 safe_load 검증 추가.
  3. SKILL.md v0.2.0 표방(em dash/content)과 게이트 구현 일치시키기 — 문서든 코드든 한쪽을 맞춤.
  4. 중복 헤딩 슬러그(-1 접미사) 모델링.
  5. preview 스크립트를 scripts/에 추가해 finish 계약을 도구로 지원.
